五、第二周不要再“学习”，直接做项目

这一点我特别建议你调整。

你现在的目标不是：

> “我要彻底学懂 Pi。”

而应该是：

> “我要利用第一周建立的架构理解，在第二周做一个能证明我理解了 Pi 的改造。”

例如可以做：

**方向 A：多 API / 多模型路由**

```text
用户
 ↓
Pi Agent
 ↓
Router
 ├── 简单任务 → Model A
 ├── Coding → Model B
 └── 长上下文 → Model C
```

这个非常适合你现在正在研究的“不同 API”。

或者：

**方向 B：Session / Memory 改造**

例如：

```text
普通 Session
      ↓
增加长期记忆层
      ↓
根据历史任务检索相关 Context
      ↓
Agent
```

或者：

**方向 C：Agent Tool 改造**

增加一个自己的 Tool，让 Agent 能完成一个原本不能完成的任务。

这三种里面，我比较倾向于 **A 或 B**，因为它们能够直接体现你第一周读懂的核心架构。

六、而且你做简历项目时，不要写成“我复现了 Pi”

这就不是“跑通 GitHub 项目”了，而是**真正做过工程改造**。
