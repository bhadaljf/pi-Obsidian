# 流式事件的交错问题：

  不同内容块（text、thinking、tool call）的流式事件不保证连续。供应商可能在同一个上游 chunk里同时吐文本、思考、工具调用的
  delta，pi会把对应事件交错发出来，比如：
  text_start → text_delta → toolcall_start → text_delta → toolcall_delta

  也就是说：文本事件之间，可能穿插着工具调用事件。消费者必须：
  - 用 **contentIndex** 来关联每个delta/end 事件和它属于哪个内容块
  - 不能假设某个块的 *_start → *_delta → *_end 序列是不间断的

# 阅读顺序
1. **`packages/agent/src/agent-loop.ts`** —— 这是核心，即 Agent 的主循环：发送请求 → 处理工具调用（tool call）→ 回传结果 → 再次发送请求。它是 Agent Runtime 的心脏。结合你刚学的 `transformMessages` 和事件系统，正好能把 README 里的概念全部串起来。
    
2. **`packages/agent/src/agent.ts`** —— Agent 类的公共 API，负责状态管理和事件订阅。
    
3. **`packages/agent/src/types.ts`** —— 你最早读过这个文件，现在回头看会有更深的理解。比如 `AgentLoopConfig` 里的每个钩子（hook），现在都能对应到实际运行逻辑。
    
4. **`packages/coding-agent/src/`** —— 看它怎么配置 Agent：注册工具、构建 prompt、以及 CLI 入口。这才是用户最终面对的东西。
