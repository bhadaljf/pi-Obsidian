## 项目真实结构速查（以仓库为准，避免读错目录）

- 入口：`packages/coding-agent/src/main.ts`、`src/cli.ts`
- Agent 会话壳：`packages/coding-agent/src/core/agent-session.ts`（超大，3342 行）
- agent loop / 核心状态机：`packages/agent/src/agent.ts`、`src/agent-loop.ts`（pi-agent-core）
- 模型统一抽象 + Provider 适配：`packages/ai/src/models.ts`、`src/providers/{openai,anthropic,google}.ts`、`src/api/*.ts`
- 工具系统：`packages/coding-agent/src/core/tools/*.ts`（read/bash/edit/write…）
- 会话持久化 / session：`packages/coding-agent/src/core/session-manager.ts` + `packages/agent/src/harness/session/`
- 扩展机制（pub-sub）：`packages/coding-agent/src/core/extensions/{loader,runner,types}.ts`
- 压缩：`packages/coding-agent/src/core/compaction/`、`src/core/agent-session.ts` 的 `compact()`

> 记法：`packages/coding-agent` 是"给用户用的东西 + 配置"，`packages/agent` 是"核心状态机"，`packages/ai` 是"把各家模型 API 抹平成统一接口"。这三层分清了，主线就通了。

## 第 1 周：搭"讲稿骨架"（每天产出都是能脱稿讲的话）

### D1 — 一条主链（最重要，先跑通再谈别的）
产出：口头能讲完的整条线——
`输入 → AgentSession.prompt() → 组 messages → agent loop 调 LLM → 流式返回 → 有 tool call? → 执行 tool → 结果回传 → 再调 LLM → 停(stopReason)`

必读文件（只为"能讲"，禁钻语法）：
- `packages/coding-agent/src/core/agent-session.ts` → `async prompt()`、`_runAgentPrompt()`
- `packages/agent/src/agent.ts` → Agent 公共 API、状态、事件
- `packages/agent/src/agent-loop.ts` → 主循环：发请求 → tool → 回传 → 再发
- `packages/ai/src/api/transform-messages.ts` → 内部消息如何转成各家 API 的 messages

### D2 — Model / Provider / API 三层抽象
产出：一句"为何这么多 API 能统一调用" + 一个具体对比例子。

必读：
- `packages/ai/src/models.ts` → `Model` 类型（913 行 `clampThinkingLevel`、`getSupportedThinkingLevels`）
- `packages/ai/src/providers/openai.ts` vs `providers/anthropic.ts` → 各自如何产出请求
- `packages/ai/src/api/transform-messages.ts` → 统一消息 → 各家格式

扛打深点候选：thinking level 的 clamp（为何要按模型能力裁剪）；不同 provider 的 tool call 格式差异如何被抹平。

### D3 — Tool 系统
产出：讲清"LLM 怎么知道有哪些工具、工具怎么被执行、结果怎么回传给 LLM"。

必读：
- `packages/coding-agent/src/core/tools/index.ts`（注册表）
- `packages/coding-agent/src/core/tools/read.ts` / `bash.ts`（挑一个简单工具追踪）
- `packages/agent/src/agent-loop.ts` 里 tool call → tool result → 再入 loop 那一段

扛打深点候选：**tool registry**（agent 与普通 chat 的本质区别）。

### D4 — Session / Context / Compaction
产出：回答"重启为何能接着聊、为何能回溯历史、压缩为何不丢记忆"。

必读：
- `packages/coding-agent/src/core/session-manager.ts`
- `packages/agent/src/harness/session/jsonl/*.ts`（持久化格式）
- `packages/coding-agent/src/core/agent-session.ts` 的 `compact()`（1790 行附近）+ `core/compaction/`
- `/tree` 相关：session 分支结构

### D5 — 两个"扛打深点"打磨
产出：选出你能扛的 2 个深点，各写 3~4 句"面试版"解释。

- **流式事件交错 + contentIndex**：text / thinking / tool call 的 delta 不保证连续，同一个上游 chunk 可能混吐多种 delta，消费者必须用 contentIndex 关联，不能假设 `*_start → *_delta → *_end` 不间断。（已在思考.md，重点打磨）
- **Agent 扩展性**：`packages/coding-agent/src/core/extensions/runner.ts` 的 `emit()` —— 发布订阅，一个事件分发给所有注册过的扩展 handler。

### D6 — 边界与"我能改进"
产出：找出 2 个能诚实指出的局限 + 想好"如果我来改会怎么改"。
现成例子（你已经发现过）：
- `agent-session.ts` 的私有转发壳 `_clampThinkingLevel()` 收了个 `_availableLevels` 参数却不用、转手让外部重新算一遍 —— 冗余，可简化。
- 拆解中你看到的其它长函数 / 重复计算。

## 核心研究问题（贯穿始终）
1. **入口**：用户请求从哪进入 `AgentSession`？
2. **调度**：`AgentSession` 如何驱动 LLM 与 Tool 循环？
3. **工具**：Tool 如何定义、注册、执行、回传？
4. **抽象**：Model / Provider / API 各负责什么？为何能统一调用多家？
5. **状态**：Session 如何管理对话历史、分支、压缩与回溯？
