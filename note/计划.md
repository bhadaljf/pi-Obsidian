## 一、真实主链

```text
main.ts → SessionManager / Runtime → AgentSession.prompt()
→ _runAgentPrompt() → Agent.prompt() → runAgentLoop() / runLoop()
→ streamAssistantResponse() → streamFunction() → assistant message
→ tool call？ → executeToolCalls() → ToolResultMessage 回写上下文
→ 再次请求模型 → stopReason / shouldStopAfterTurn → agent_end
```

* **Q：模型怎么知道有哪些工具、怎么调？**
	* 服务端把每个工具的 **name + description + parameters(schema) 序列化**进请求的 tools 字段一起发给模型。模型在提示里"看到"这些工具，按 **description 判断要不要用**、按 **schema 生成合法参数**，然后在自己返回的 **assistant 消息里夹一个 toolCall**(工具名 + arguments)。所以<span style="color : red"> 模型不执行任何东西</span> ，它只"指名道姓"要用哪个工具、给什么参数
* **Q：收到 tool call 后服务端做什么？**
	* agent 收到含 toolCall 的 assistant 消息后，进入工具执行：**按 toolName 去工具注册表/当前上下文里找到那个工具，校验参数，调它的 execute() 真正执行**，把**结果包成一条 ToolResultMessage 回写进对话上下文**，再让模型继续——模型看到工具结果后，要么再调工具，要么输出最终答案。这就是"Agent 与普通 Chatbot 的区别"：它能主动调工具、拿到结果再继续推理。
* **Q：为什么用注册表？**
	* **方便统一管理。模型只给工具"名字"**。注册表 = "名字→工具定义/执行者"的索引，**让服务端按名快速找到执行者**，同时负责去重、启停/白名单/黑名单管理、以及把内置/扩展/自定义工具统一到一个入口。没有它，每次都得从一堆工具里现找、也管不了"哪些该给模型"。

## 三、抽象程度与主体辨识

默认采用“关系优先、轮廓舍弃”的抽象方式，但根据照片主体自适应处理：

- 标志性建筑或具有独特形状的主体：允许保留一至三个最低限度的身份特征，例如特殊外轮廓、代表性负空间、檐线、塔身收分、拱洞、尖顶或层叠节奏。不得描绘窗户、砖石、斗拱、雕刻、栏杆花纹等细节。
    
- 有机群体，如气球、树冠、云团或灯光：用相互重叠的柔和有机色块表达密度和上升、扩散或聚集关系，不绘制内部图案和写实高光。
    
- 人群：每个人只用一个连续、不规则的短竖墨点或轻微收分的色块表示。头肩与身体连成一体，不单独绘制圆形头部、四肢、面孔和衣服。通过高低、宽窄、间距、倾斜和前后遮挡形成节奏。
    
- 栏杆、道路、地平线或水岸：压缩为一至两条细水平轴和少量不规则中断。
    
- 小型代表性物件，如铃铛、灯笼或风铃：只保留两至三个平面标记。通过比例和位置建立辨识，不使用金属高光、真实体积、内部结构或写实材质。
    

原则是：保留“最低必要辨识度”，而不是复刻物体。
