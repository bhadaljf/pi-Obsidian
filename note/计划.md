## 目标（面试导向）

两周左右完成第一个项目的核心准备：围绕真实代码讲清 pi Agent 的关键链路、设计取舍和两个深度机制，并使用 AI 完成一项有边界的优化，解释、测试和验证每处改动。

项目一是 pi Agent 优化；项目二是业务 Agent，补足 RAG、Workflow、Eval、业务指标和落地能力。AI 加速实现，自己掌握设计、审查、调试、测试和面试解释。

## 一、真实主链

```text
main.ts → SessionManager / Runtime → AgentSession.prompt()
→ _runAgentPrompt() → Agent.prompt() → runAgentLoop() / runLoop()
→ streamAssistantResponse() → streamFunction() → assistant message
→ tool call？ → executeToolCalls() → ToolResultMessage 回写上下文
→ 再次请求模型 → stopReason / shouldStopAfterTurn → agent_end
```

主要代码位置：`packages/coding-agent/src/main.ts`、`src/core/agent-session.ts`、`packages/agent/src/agent.ts`、`src/agent-loop.ts`、`packages/ai/src/models.ts`、`src/api/transform-messages.ts`、`packages/coding-agent/src/core/tools/`、`session-manager.ts`、`core/compaction/`、`core/extensions/`。

## 二、面试知识库映射

| 面试能力 | pi 项目证据 |
|---|---|
| Agent 架构、ReAct / Workflow | `runLoop` 的模型—工具循环 |
| Tool/Function Calling | 工具定义、参数准备、执行、结果回传 |
| Context Engineering | `transformContext`、消息转换、上下文构建 |
| Model / Provider | `Model`、`Provider`、`streamFunction`、`transformMessages` |
| Memory / Session | JSONL、session tree、`buildSessionContext` |
| Compaction | token 估算、阈值、摘要、继续运行 |
| 流式输出 | partial message、事件流、`contentIndex` 交错 |
| 稳定性 | stopReason、截断 tool call、错误结果、重试边界 |
| Extension / Skill / Harness | ExtensionRunner 的注册和事件分发 |

RAG、BM25、Rerank、Query Rewrite、业务 ROI、FastAPI 业务接口主要放到第二个业务 Agent 项目。

## 三、两周链路计划与每日任务

完成标准是链路能讲通并能对应面试问题，不以代码行数为标准。每日先自行划重点，再阅读重点区段。

### D1：入口到 AgentSession

链路：CLI 启动 → SessionManager/Runtime → `AgentSession.prompt()`。

- [ ] 阅读 `main.ts` 中参数解析、SessionManager/Runtime 创建和初始消息进入主路径
- [ ] 精读 `prompt()` 的输入预处理、扩展命令判断、输入事件和消息准备
- [ ] 精读 `_runAgentPrompt()` 如何把消息交给内部 Agent、结束后如何收尾
- [ ] 记录每步输入、输出、状态变化和下一个节点；跳过 UI、主题、诊断细节
- [ ] 回答：AgentSession 与 Agent 为什么分层？
- [ ] 产出：入口链路图、1 分钟回答、3 个疑问

### D2：Agent 公共 API 到主循环

链路：`Agent.prompt()` → `runPromptMessages()` → `runAgentLoop()` → `runLoop()`。

- [ ] 理解 prompt 的输入标准化、activeRun 检查和运行启动

### D3：模型响应与停止

- [ ] 产出：工具可用链路图和一个工具结构说明

### D5：工具执行与结果回传

链路：tool call → 准备/校验 → 执行 → 结果封装 → 回到 loop。

- [ ] 追踪 `prepareToolCall()`、工具查找、参数准备和未知工具处理

### D6：Model / Provider 抽象

## 五、执行原则

1. 以链路是否讲通作为产出，不以函数数目或代码行数作为产出。
2. 每个主题对应面试问题和项目证据。
3. TS 只补当前链路用到的 `async/await`、`Promise`、类型/接口、联合类型、泛型、回调、类型守卫、可选链、`for await...of`。
4. AI 生成代码必须经过自己审查、运行和边界测试。
5. 不把所有关键词强行加入 pi；RAG 和业务落地在第二个业务 Agent 项目中完成。
